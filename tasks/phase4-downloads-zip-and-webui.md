# Фаза 4: скачивание файлов, ZIP и стандартный Web UI

Статус: **Не начата**.

Предпосылка: завершена [фаза 3](phase3-torrserver-and-streaming.md), прочитан её отчёт. Основание: [SPEC.md](../SPEC.md), §§8–12, 14. Отчёт: tasks/implementation/phase4-report.md.

## Цель

Дать пользователю готовые downloads и управление плагином в штатном Deluge Web UI. Web UI может работать отдельно от daemon; доступ к его файловой системе для скачивания не требуется.

## Задачи

### 1. Допуск и download tickets

- Проверять права owner/admin через авторизованный RPC; выдавать ограниченные по назначению и времени tickets, связанные с экземпляром торрента и выбранным файлом/ZIP.
- Атомарно согласовать готовность, reservation, начало передачи, изменение политики и cleanup.
- Корректно освобождать reservations при истечении ticket, отмене, ошибке и завершении передачи; исключить бесконечную защиту из-за утечки ticket.
- Отклонять чужие, просроченные, несовместимые по назначению и устаревшие после delete/re-add tickets.
- Формировать доступный клиенту URL core listener по public_base_url. Бинарные данные не передавать через Deluge RPC.

### 2. Отдельный файл

- Разрешать выдачу только полностью загруженного payload-файла по источнику готовности Deluge/libtorrent. Не запускать догрузку по действию «Скачать».
- Поддержать GET/HEAD, single Range, корректный Content-Disposition и Unicode-имена.
- Проверять соответствие содержимого, поведение при изменении готовности/recheck, disk error и ручном удалении после допуска.
- Применять backpressure и общий lifecycle; download защищает от cleanup, но не увеличивает playback-счётчик.

### 3. ZIP всего торрента

- Проверять готовность всех payload-файлов, включая skipped; 100% wanted-progress не является достаточным условием.
- Потоково формировать ZIP64 в режиме STORE с правильным составом, каталогами, CRC, Unicode и нулевыми файлами.
- Не создавать полный архив на диске или в памяти. Раздельно учитывать payload-буферы и служебную память числа ZIP-записей.
- Обработать traversal, абсолютные пути, symlinks и коллизии имён по ТЗ, не выдавая чужие данные.
- Обработать отмену и ошибку после начала HTTP-ответа; не завершать повреждённый архив как успешный. Возобновление ZIP через Range не обещать.

### 4. Управление в Web UI

- Реализовать настройки плагина, проверку доступности core и совместимости версий, ошибки применения настроек.
- Добавить видимый временный/постоянный статус и действия переключения в обе стороны, публикацию в TorrServer и причины отсрочки cleanup.
- Показывать «Стриминг» по playback-сессиям с debounce; preload, file download и ZIP отражать отдельно.
- Добавить действия скачивания готового файла и всего готового торрента. Объяснять недоступность действия, не запускать скрытую догрузку.
- Обновлять статусы без перезагрузки Web UI, корректно обрабатывать исчезновение торрента и одновременные действия пользователя.
- Проверить Web UI и daemon в отдельных окружениях без общего диска; основное управление Deluge остаётся работоспособным при отключении плагина.

### 5. Makefile, CI и README

- Добавить рабочие make test-web и make test-downloads; включить обязательные сценарии в test/check и checks.yml.
- Проверять, что build включает необходимые web-ресурсы, а smoke использует установленный artifact.
- Описать в README реальные действия: смена политики, публикация, просмотр статуса, file/ZIP, условия готовности и диагностика неработающей download-ссылки.
- Явно указать отсутствие ZIP resume и необходимость доступности core listener с устройства пользователя.

## Проверки

Обязательны make check и A17–A24; повторить A10/A13 с настоящими file/ZIP/ticket, A14 с устаревшими tickets и A26 для downloads. Большие ZIP проверять обычным независимым архиватором, CRC и сравнением состава; отдельно проверить >4 GiB и >65535 записей.

UI-проверки должны покрывать RPC-ошибки, недоступный core, запрет скачивания неготовых данных и раздельные индикаторы. Хотя бы один smoke проходит в настоящем браузере с установленным web artifact; одних mocks недостаточно. Записать используемые браузер и runtime.

## Definition of Done

- [ ] Готовый отдельный файл скачивается с корректными байтами, именем и Range; неготовый отклоняется.
- [ ] Готовность ZIP учитывает все payload-файлы, включая skipped, и не вызывает догрузку.
- [ ] ZIP64 проверен по составу/CRC, большим размерам и числу записей без полного промежуточного архива.
- [ ] Tickets, reservations, отмена и защита от cleanup работают с настоящими file/ZIP-передачами.
- [ ] Web UI позволяет управлять настройками, постоянством и публикацией.
- [ ] «Стриминг», preload и downloads отображаются раздельно и своевременно обновляются.
- [ ] Web UI работает отдельно от daemon без общего диска; права и доступность URL проверены.
- [ ] make test-web/test-downloads включены в make check и CI; проверки проходят.
- [ ] README содержит проверенные пользовательские сценарии и ограничения downloads.
- [ ] Отчёт и индекс фаз обновлены; A17–A24 подтверждены с указанием среды.
