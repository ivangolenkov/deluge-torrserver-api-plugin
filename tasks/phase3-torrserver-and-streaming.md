# Фаза 3: TorrServer API и streaming QoS

Статус: **Не начата**.

Предпосылка: завершена [фаза 2](phase2-retention-and-transfer-lifecycle.md), прочитан её отчёт. Основание: [SPEC.md](../SPEC.md), §§5–7, 10–12, 14. Отчёт: tasks/implementation/phase3-report.md.

## Цель

Обеспечить воспроизведение незавершённого файла и перемотку в Lampa/Num через встроенный HTTP listener. Временные приоритеты должны следовать чтению, учитывать несколько клиентов и корректно сниматься.

## Задачи

### 1. Совместимый HTTP-контракт

- Реализовать маршруты и DTO из ТЗ по fixtures фазы 0: add/list/get/rem, file list, preload/stat/play, cache, settings и согласованный viewed-контракт.
- Сохранить правила публикации, владельца, постоянства и повторного add; не раскрывать через TorrServer произвольные торренты daemon.
- Реализовать точную нумерацию файлов, hash aliases и обработку ещё не полученных metadata. Не включать pad-файлы как пользовательские.
- Соблюсти различие rem, drop/wipe и автоматического удаления с данными согласно ТЗ.
- Поддержать CORS *, OPTIONS, GET/HEAD и все требуемые single Range. Ошибки, Content-Length, Content-Range и выдаваемые байты должны соответствовать контракту.

### 2. Чтение и отмена

- Реализовать async reader по выбранному в фазе 0 алгоритму: ждать подтверждённые pieces и читать через libtorrent/адаптер, не возвращая sparse-ноли.
- Продвигать окно чтения внутри одного длинного GET; новые Range-запросы не должны быть условием продвижения загрузки.
- Обрабатывать границы файлов/pieces, короткое чтение, отсутствие metadata, timeout, hash error и удаление экземпляра.
- Ввести ограниченные буферы и очереди, backpressure и отмену ожиданий при disconnect, disable, move/recheck/remove.
- Подключить реальные playback/preload к общему lifecycle фазы 2; HEAD/stat не создают ложный просмотр и QoS.

### 3. QoS и несколько клиентов

- Агрегировать окна всех активных сессий; deadline/priority одного клиента не должен отменять потребности другого.
- При seek оперативно обновлять требуемую область, удалять ненужные overrides и сохранять debounce-защиту между связанными запросами.
- Разделять playback, preload и обычные downloads; считать наблюдаемую HTTP-активность, не обещать точного числа зрителей.
- Проверить взаимодействие с file priorities, first/last, pause и очередью. Последнее пользовательское решение имеет приоритет над восстановлением старого snapshot.
- Реализовать проверенное восстановление после disable, restart и resume-data; временные streaming overrides не становятся постоянными.
- Не менять глобальные настройки Deluge, влияющие на чужие торренты, ради одной сессии.

### 4. Наблюдаемость и документация

- Добавить status fields/RPC для playback/preload, защищённости, ожидания pieces и причин ошибок. Полный UI оформляется в фазе 4.
- Добавить диагностику задержки reactor, буферов и lifecycle без вывода секретов URL/tickets.
- Расширить Makefile (make test/check) и checks.yml проверками протокола, reader и QoS на локальном seed.
- Дополнить README работающими настройками listener/public_base_url, подключением Lampa/Num, смыслом «Стриминг» и диагностикой буферизации.

## Проверки

Обязательны make check и реальные Lampa/Num на зафиксированных версиях: добавление, список, preload, просмотр незавершённого файла, seek вперёд/назад, остановка и повторное открытие.

Проверить A02–A08, A16, streaming/preload-части A10 и A20–A21, соответствующую часть A26. Сравнивать содержимое HTTP-ответов с эталоном, а не только статус 206. Два клиента с разными позициями и общий граничный piece должны иметь отдельные сценарии. Restart тестировать после фактического сохранения resume-data.

Для контрактных fixtures автоматизировать воспроизведение запросов. Прямой HTTP-тест не заменяет ручную проверку обязательных клиентов; если клиент недоступен, записать незавершённый пункт.

## Definition of Done

- [ ] Требуемый TorrServer-контракт реализован и проверен fixtures и реальными Lampa/Num.
- [ ] Незавершённый файл воспроизводится; Range/HEAD/seek возвращают корректные статусы, заголовки и байты.
- [ ] Окно pieces продвигается в одном длинном GET; отмена прекращает ненужную работу.
- [ ] Несколько playback/preload-сессий согласованно управляют QoS и защитой от cleanup.
- [ ] Пользовательские priorities/pause/queue сохраняются, включая disable и crash/resume.
- [ ] Backpressure, лимиты буферов и неблокирующее выполнение подтверждены.
- [ ] Наблюдаемое состояние и диагностика доступны web-части через RPC/status fields.
- [ ] make check проходит; новые автоматические проверки включены в CI.
- [ ] README описывает проверенное подключение и ограничения streaming.
- [ ] Отчёт и индекс фаз обновлены; частичные и ручные проверки явно обозначены.
