# Фаза 7: обновление плагина из настроек

Статус: **Завершена**. [Фактический отчёт и ограничения](implementation/phase7-report.md).

Основание: запрос пользователя от 2 ноября 2026 года. Пользователь использует
systemd и просит поддержать перезапуск независимо от способа развёртывания.
Прочитаны SPEC, план поставки фазы 5 и отчёт завершённой фазы 6. Эта отдельная
задача не закрывает оставшуюся приёмку фаз 3/5.

## Поведение и порядок реализации

1. В Preferences → Stream добавить проверку стабильного GitHub Release,
   текущие версии core/web, доступную версию, ссылку и явное действие обновления.
   Проверка не устанавливает обновление автоматически.
2. Источник — `ivangolenkov/deluge-torrserver-api-plugin`. Проверять версию,
   совместимость каждого процесса, manifest и SHA-256 перед установкой.
   Ограничить сеть, размеры, параллелизм; выполнять I/O вне reactor.
3. Только администратор Deluge может запускать операции. Web-часть координирует
   подготовку на обоих узлах через авторизованный RPC; общий диск не требуется.
   Локальный установщик web — необходимая часть поставки web-плагина,
   торрент-функции по-прежнему находятся в core.
4. Сначала скачать и проверить оба пакета, затем установить. Сохранять старый
   egg, не перезаписывать загруженный Python-код и не использовать disable/enable.
   Ошибка или частичное обновление должны быть видны; повторные запросы ограничены.
5. Для штатных Linux entry points Deluge проверить завершение reactor и повторный
   exec процесса с прежними параметрами/профилем и без повторной daemonization.
   Это не требует root, systemctl или Docker socket. Неизвестный способ запуска
   должен давать понятный отказ автоматического перезапуска до установки.
6. Успех означает новые версии после reconnect, а не завершённое скачивание.
   Предупредить о прерывании активных передач; сохранить настройки, SQLite,
   временность/FIFO, metadata/viewed и payload при штатном restart.
7. Проверить unit, реальную установку и restart core/web, Chromium и make check;
   обновить README, Makefile/CI по необходимости и фактический отчёт.

## Definition of Done

- [x] Проверка GitHub Release и состояния «нет обновлений»/ошибок работают в UI.
- [x] Версия, runtime и SHA-256 проверяются до установки на каждом узле.
- [x] Операции авторизованы, I/O ограничен и не блокирует reactor.
- [x] Проверенные core/web artifacts устанавливаются без общего диска.
- [x] Штатные процессы перезапускаются без зависимости от service manager.
- [x] Состояние торрентов/SQLite сохраняется; disable/reset не используется.
- [x] Ошибки подготовки/установки/перезапуска не дают ложного успеха.
- [x] Native и браузерные проверки, make check и документация завершены.

Подтверждены штатные foreground entry points Linux в изолированных процессах,
оба Python runtime и обе архитектуры (x86_64 под эмуляцией). Сам update-сценарий
проверен с раздельными профилями одного контейнера; полная матрица service managers,
forking units и обновление двух разных машин отдельно не проверялись. Реальный
GitHub пакет проверен без установки; native update использует локальный fixture.

Новый сценарий A28: проверка, установка и перезапуск из Web UI; отсутствие
релиза, несовместимый пакет, неверный checksum, отказ записи, конкуренция,
частичная недоступность, split core/web и сохранение состояния.
