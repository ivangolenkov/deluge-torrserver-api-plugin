# Фаза 2: FIFO-очистка и жизненный цикл передач

Статус: **Не начата**.

Предпосылка: завершена [фаза 1](phase1-core-persistence-and-ci.md). Основание: [SPEC.md](../SPEC.md), §§4, 8.1, 11–12. Отчёт: tasks/implementation/phase2-report.md.

## Цель

Безопасно удалять временные торренты при превышении количества и предоставить единый механизм защиты для будущих stream/preload/file/ZIP передач.

## Задачи

### 1. Допуск и защита

- Создать общий coordinator для смены политики, допуска передачи, ticket-reservation и удаления конкретного экземпляра.
- Реализовать refcount с однократным release, ограниченный lifetime ожиданий/резервов и debounce с версионированием таймеров.
- Защищать stream, preload, файл, ZIP и ticket reservation через одну модель. Для ещё не реализованных HTTP-путей проверить контракт контролируемыми fake-передачами.
- Не делать stats/HEAD источником длительной защиты и не считать фоновую загрузку активной передачей плагина.
- При удалении закрывать допуск, а поздние callbacks/таймеры старого record_id игнорировать.

### 2. FIFO

- Запускать очистку после успешного add/перевода во временный, уменьшения лимита, восстановления и освобождения защиты.
- Выбирать только самый старый временный экземпляр; защищённого старейшего не обходить.
- Подтверждать политику и идентичность перед удалением. Успешное закрепление должно исключать последующее автоматическое удаление.
- Учитывать recovery_required фазы 1: после crash не запускать автоочистку до подтверждения администратора; не сбрасывать это требование clean restart. После явного disable старые связи недействительны, после обычного stop/start политика сохраняется. Проверка admission фазы 1 не заменяет проверяемый deletion plan и повторную проверку путей.
- Удалять через Deluge вместе с данными; отличать принятую команду от подтверждённого завершения асинхронного удаления.
- Ошибка cleanup не отменяет успешный add. Неуспешный add не инициирует cleanup.
- При ошибке/защите остановить проход, сохранить причину и повторить ограниченно; не переходить к более новым кандидатам.
- Не включать очистку по диску, размеру, TTL или времени просмотра.

### 3. Файлы и восстановление

- Для новых plugin-added торрентов обеспечить отдельные каталоги; для существующих работать с актуальными путями Deluge без обязательного переноса.
- Проверять shared/overlapping paths, symlinks, переименование и move; не удалять весь download_root.
- Сохранять журнал стадий удаления и проверяемый план файлов. После crash повторять только безопасно доказуемую операцию; неоднозначность оставлять диагностируемой.
- Обрабатывать внешнее удаление/повторный add, отсутствие metadata и частичный отказ удаления данных.
- При ошибке/потере БД отключать автоматическое удаление, не делая все торренты временными.

### 4. Инструменты и документация

- Добавить детерминированные тесты конкурентности и fault injection в make test-integration/check и checks.yml.
- Обновить README: FIFO, default лимит, двусторонняя смена статуса, удаление данных, допустимое временное превышение и причины отложенной очистки.
- Описать восстановление незавершённого удаления и различие между автоочисткой плагина и ручным действием в Deluge.

## Проверки

make check; сценарии A09–A15 и A22 с реальной SQLite/Deluge. Для A10 проверить все типы защит через lifecycle API; реальный stream/file/ZIP проверить повторно при их появлении в фазах 3–4. A26: нехватка места не вызывает дополнительное удаление.

Обязательные гонки: cleanup против закрепления; cleanup против старта передачи; delete/re-add против release; рестарт между записью намерения и фактическим удалением; истечение ticket/debounce против нового допуска. Не полагаться только на sleeps и случайный порядок.

## Definition of Done

- [ ] Все типы передач используют общий допуск и защиту экземпляра.
- [ ] FIFO удаляет старейшего только при превышении количества и соблюдает защищённую голову очереди.
- [ ] Смена постоянства и старт передачи согласованы с удалением; нет double release и утечек защиты.
- [ ] Ошибки add/cleanup не смешиваются; retry ограничен и останавливается при shutdown.
- [ ] Shared paths и небезопасные пути не приводят к удалению чужих файлов.
- [ ] Crash/частичное удаление/внешнее удаление корректно согласуются с журналом и Deluge.
- [ ] Проверены A09–A15/A22 и относящаяся часть A26; ограничения fake-передач указаны.
- [ ] Makefile и checks.yml включают новые обязательные проверки; make check проходит.
- [ ] README описывает фактическую политику и восстановление; отчёт и индекс фаз обновлены.
