# Клиентская приёмка Lampa/Num: фаза 3

Статус: **не выполнена для нового backend**. HTTP/native tests не заменяют
просмотр настоящего видео. [Отчёт](../tasks/implementation/phase3-report.md).
Пользователь выполнит клиентскую приёмку самостоятельно позже. Она остаётся
открытой проверкой продукта, но по его решению не блокирует публикацию релиза.
Историческая Lampa 3.4.4 — module-level capture с эталоном MatriX.147.1,
не приёмка плагина. Версию Num ещё нужно зафиксировать на реальном устройстве.

## Стенд

- Изолированный тестовый профиль Deluge 2.2.0, Python 3.11, libtorrent 2.0.8.
- Собранный текущий egg, настроенный owner и доступный клиенту HTTP/public_base_url.
- Легальный настоящий видеофайл/торрент с локальным seed, а не публичный swarm как
  обязательная зависимость. `payload.bin` автоматических тестов — **не видео**.
- Доступное устройство/эмулятор Num и Lampa. Записать версии, OS, плеер/decoder,
  устройство, размер/тип медиа, архитектуру daemon и версии плагина.
- Контролируемо ограничить скорость seed как действие пользователя, чтобы начать
  просмотр незавершённого файла. Плагин сам не меняет глобальные лимиты/очередь.
- Сохранить исходные file priorities/skip/first-last/pause/queue для сравнения.

## Для каждого клиента

1. Подключиться к HTTP listener, не к deluge-web. Проверить echo/список: чужие
   неопубликованные торренты не видны, обычный native add сам не публикуется.
2. Добавить v1 magnet или HTTP `.torrent`: проверить название и file list,
   состояние ожидания metadata и выбор файла с корректным 1-based id.
3. Запустить preload: проверить готовые байты/ошибки, отсутствие «Стриминг» до
   playback. Повторный preload не создаёт бесконечную защиту/новые дубликаты.
4. Начать настоящее видео, когда файл ещё не готов целиком. Убедиться в корректном
   декодировании и продвижении загрузки без обязательного повторного Range.
5. Seek вперёд, назад и к концу; проверить остановку и повторное открытие.
6. Запустить два чтения с разными позициями, закрыть одно: второе продолжает
   работать. Зафиксировать поведение при фоновом native скачивании.
7. На паузе торрента и всей сессии прочитать **готовый** диапазон; то же для файла
   «Не скачивать». Неготовый диапазон должен сообщать blocked/conflict, не снимать
   паузу/skip и не выдавать sparse-ноли. Проверка/recheck сама остаётся native.
8. Убедиться, что last file priorities, skip, first-last и pause/queue не изменены
   плагином. Остаточные числовые piece priorities допустимы по согласованию.
9. Проверить list/set/rem viewed, сохранение после обычного daemon restart.
10. Проверить, что drop/wipe/закрытие страницы не удаляют торренты; rem с активной
    передачей отклоняется. FIFO не обходит защищённого старейшего.
11. После disconnect/медленного клиента/disable исчезают ожидания, buffers и
    leases; crash обнуляет HTTP-сессии, публикация/FIFO требуют admin confirmation.

## Что прислать

Для каждого шага: Passed/Failed/Not run, версия клиента/плеера, последовательность
действий, ожидаемый и фактический результат. При сбое — время, HTTP status/error,
безопасный `stream.get_diagnostics(1)` и фрагмент логов. Не включать пароли,
probe/download tokens, приватные URL/trackers/passkeys и содержимое metadata.data.

Не отмечать всю фазу выполненной только по одному успешному старту видео или
HTTP 206. Для подтверждения клиентской приёмки нужны результаты обоих клиентов.
